# 开发、调试与验证

返回入口：[agent.md](../agent.md)

## 命令

```bash
npm install          # 依赖源是公司 artifactory
npm run dev          # Vite 开发服务器 http://127.0.0.1:5180/，热更新
npm run build        # tsc --noEmit + vite build，产物在 dist/
npm run preview      # 本地预览 dist/
npm run typecheck
npm run build:lib    # 独立模块：dist-lib/（ESM + 类型 + assets），见 library.md
```

依赖版本是锁定的：three 0.186.1、@types/three 0.186.0、typescript 5.8.3、vite 8.3.4。需要 WebGL2，不支持时显示 `#fallback`。

## 调试工具 `window.__mb`

dev 模式自动加载，构建版加 `?debug=1` 加载（落地页带 `?debug` 时还会关闭 autoPause，方便同步步进）。作为模块使用时传 `debug: true`。实现在 `src/app/debug.ts`。

| 方法 | 用途 |
|---|---|
| `stepFrames(n)` | 同步推进 n 帧。页面在后台时 rAF 会被节流，测量前先用它 |
| `probe()` | 采样一组固定位置（天空、山、地面、接触点、阴影、球的各部位）的像素颜色 |
| `silhouette()` | 小球轮廓内外 12 个方向的亮度差，`separation mean` 越大越清楚 |
| `lumaGrid(cols, rows, x0, y0, x1, y1)` | 指定区域的亮度数值网格 |
| `lumaMap(...)` | 拉伸对比后的 ASCII 亮度图 |
| `idMap(...)` | 按物体着色的 ASCII 图，看谁挡住了谁 |
| `cloudMap()` / `readMap(x, z)` | 云层 / 交互贴图读数 |
| `withPreset(name, patch, fn)` | 临时改预设、渲染、执行 fn，然后自动还原 |
| `presets` | 实时预设对象：改完调用 `app.weather.snap()` 立即生效 |
| `gltfRoundTrip()` | 验证 GLTF 模型加载路径 |
| `assets(true/false)` | 立即切换照片贴图 + HDR 天空 / 程序化版本，返回各素材加载状态，用来做同一帧的前后对比 |
| `u` | 共享 uniform 对象（`u.ground.uGTex`、`u.terrain.uRockTex`、`u.sky.uHdrOn` 等），可以单独开关某一项 |
| `shot(name)` | 把当前帧存成 JPEG，需要预览服务器支持 `POST /__shot/<name>`（launch.json 里的 `motion-ball-check` 支持，存到 `/tmp/claude-504/shots/`） |
| `app` | App 实例（weather、rig、ball、post、terrain、envAssets…） |

调参示例：

```js
__mb.withPreset('sunny', { exposure: 1.1, ballEnv: 0.7 }, () => __mb.silhouette())
```

## 改动后的验证清单

1. `npm run build` 通过（含类型检查）
2. 六种天气都没有 GL 错误：`__mb.app.renderer.getContext().getError() === 0`，控制台无 `[shader patch] anchor not found` 警告
3. 小球可读：晴天 `silhouette()` 的分离度约 20 以上，柔光天气约 10 以上
4. 常驻背景友好：全画面最亮处不刺眼（约 240 以下），连续帧亮度不闪烁，太阳默认不入画
5. 远山有层次：近处的山明显比天空暗，越远越淡
6. 多种比例都要看：1440×900、超宽（约 2000×946）、手机 375×812
7. 性能：1440×900 下每帧约 13–20 ms，雨、雾最重；照片贴图约多 1–2 ms
8. 贴图不重复、不闪：近景地面横向亮度的自相关峰值应在 0.15 以下（之前 1.4 m 的小贴图重复时是 0.2–0.4），开关贴图前后连续帧的亮度差不应变大

## 已知坑

- **场景雾会吃掉远山**：高调画面经 AgX 压缩后山会消失，所以远山不走场景雾，单独用 `mtnHaze` 曲线（`Terrain.ts` 的 `applyRangeAtmosphere`）。
- **`envMapIntensity` 不生效**：设置了 `scene.environment` 后 three 会用 `scene.environmentIntensity` 覆盖材质值，要调单个物体的环境光必须走 shader uniform（例如 `uEnvGain`）。
- **bloom 罩雾**：three 自带的高通会把过阈值像素整块送进 bloom，这里已换成只送超出部分（`BLOOM_HIGHPASS_FRAG`），不要改回去。
- **逆光会发白**：太阳在球后方时，压低强度只会变成一层灰雾。常驻背景应该保持太阳不入画，用侧光或顺光。
- **高光肩部**：`white` 的拐点要窄，只压最顶端；拐点太宽会把整片天空压成灰。
- **shader 注入锚点**：`inject` 找不到锚点时只会警告、不会报错，升级 three 后要检查控制台。
- **CPU 地形生成**：约 11.5 万顶点，启动时生成约 30 ms，加细网格时注意启动耗时。
- **三角形绕序**：自己拼的 `BufferGeometry` 要让三角形从可见一侧看是逆时针，并且和法线方向一致。远山和伞面都曾经绕反过：远山被画成"里面朝外"、阳光照不上、也不积雪，透明伞面因为菲涅尔算反而整片发白。
- **条状粒子**：雨、溅水、沙、滴水是在顶点着色器里沿速度方向拉出来的四边形，两条轴的顺序决定正反面。顺序反了会被背面剔除，整场雨都看不见（以前就是这样）。现在已经设成双面渲染并修正了轴序。
- **粒子与景深**：粒子不写深度的话，景深会用它背后远景的模糊半径，近处的水滴会被糊掉；所以粒子的核心写深度。
- **透明材质与大气**：预乘 alpha 的半透明层叠加雾或薄雾时，加进来的光要乘上它的覆盖率，否则每一层都会额外多加一整层雾（见伞面补丁）。
- **阴天里的太阳高光**：太阳光的硬高光（湿地面、球、伞的镜面反光）会乘上 `atmos.uSunSpec`，即太阳圆盘可见比例，由 `cloudCover` 算出（`App.applyWeather`）；全阴天时为 0。地面高光另外做了软限幅（`Ground.ts`）。不要去掉这两步，否则雨天积水会把太阳照成一大片过曝白光，水面涟漪还会让它闪烁。
- **清晰度**：和参考图对比时，把画面缩到参考图单格大小（590 px 宽），在右侧区域统计亮度标准差和拉普拉斯均值。但这两个数只能做参考：曾经用局部对比（clarity）和强锐化把数值刷高，结果云和山出现油画式的涂抹和描边，用户评价从 85 分掉到 30 分，这类全屏滤镜不要再加。真正有效的是渲染分辨率、`dof` 保持在 1 左右、去掉色差，以及几何和材质本身的细节（比如远山岩石的细节法线）。
- **`idMap`**：调试用的纯色材质必须设置 `toneMapped: false`，否则 AgX 会把颜色压淡，物体识别会错。
- **各向异性过滤很贵**：地面和远山贴图开 16× 时每帧多约 5 ms（远山三平面投影 × 两种尺度最明显），4× 只多约 1.5 ms。`EnvAssets.loadSet` 里地面用 4×，远山用 1×。
- **分支里的纹理采样**：按像素条件（比如距离）跳过采样时，分支里不能用隐式导数的 `texture()`，要在分支外算好梯度用 `textureGrad()`（`tileVariants` 就是这样做的），否则分支边界会出现 mip 错误的细线。
- **HDR 天空不要整体替换探针里的云**：曾经让照片天空直接替换探针自己的云，晴天的白云亮度没了，小球正面暗了约 10 个色阶并偏蓝。现在只把照片相对自身模糊版本的起伏乘上去。
- **GLSL 保留字**：`smooth`、`flat` 是 GLSL ES 3.0 的插值限定符，不能当变量名。
- **透明薄层上的细节会被景深糊掉**：伞面不写深度，景深就按它背后的远景去虚化，伞上的水珠、卷边全被糊没。现在额外画一遍只写深度的伞面（`CANOPY_DEPTH`，只在水珠、卷边、缝线处写），这些细节就按伞的距离对焦。同理，近处雪花的散景是单独一遍不写深度的绘制，否则大光斑会把后面的雪花挡掉。
- **透明伞在阴天里看不见**：薄膜反射的是和身后一样亮的天空，加多少反射都看不出来。参考图里伞比天空亮得多，是因为天空暗、光从上方和左前方来。所以雨天把天空压暗到约 130，加了左前方的柔光，伞面散射按头顶的天光和主光来算（`totalDiffuse + cSkyUp`）。
- **高调场景的纹理**：雪天曝光太高时，AgX 会把高光压平，雪地纹理和小球轮廓都看不出来。雪天曝光要低一些（0.92），用暖色主光加冷色天光做出明暗，而不是加对比度滤镜。
- **雪帽要跟着“头”走，不能粘在球身上**：小球的眼睛（`gaze`）反应很快，身体朝向靠弹簧慢慢跟上，两者最多差约 24°。雪帽以前粘在身体坐标里，看起来像一顶松垮的帽子在脸上滑、还带惯性。现在雪的方向存在“头部坐标”里（`BallBrain.headBasis`，即身体再转过目光的角度），实测和脸的偏差小于 1°。
- **球的立体感来自主光，不是补光**：以前机位侧的补光和较强的天空环境光把球照得很平（球面明暗只差约 26 级，参考图约 100 级）。现在用侧方的人像主光 `key` 加较低的 `ballEnv` 做出明暗交界，补光基本为 0。
- **月亮在画面里**：太阳一直放在画外，月亮却在画内。它的日晕（`sunGlow`）会把附近的雾、远山一起照亮，所以夜里 `sunGlow` 只有 0.15。
- **远山发灰、没层次的原因**：深色的山几乎全被空气透视的雾色盖住；顺光或逆光时朝向镜头的山坡在阴影里，起伏也看不出来。有效的做法是侧光、降低 `mtnHaze`，以及把森林、岩石在掠射角下的天空反光压低（`Terrain.ts` 的 DEM 分支里 `indirectSpecular *= 0.2`）。用噪声给山体加高频细节只会出现斑驳的噪点感（之前的问题），细节应该来自真实的高程。
- **低平的地形会和地面 z-fighting**：真实地形里高度接近 0 的平地被整体压到地面以下（`applyDem`，低于 4–14 m 的部分下沉 15 m），地面平面也扩大到 60 km，相机远裁剪面改为 40 km。
- **背景发虚的头号原因是景深**：景深合成时，模糊半径（CoC）超过约 0.45 px 的像素会换成半分辨率的散景图。`dof: 1` 时远处 CoC 约 1.5 px，整片山和天空等于半分辨率显示。现在晴天 `dof` 为 0.35（多云/大风 0.5，雪 0.6，雾 0.7，雨 0.8），远景保持全分辨率，只有脚边的地面稍微虚化。富士山的细节测量值（3 px 尺度的拉普拉斯均值）从 1.18 提升到 2.67。
- **地形细节贴图的分辨率**：富士山在画面里约 3 m/像素，原来 z12 的细节图每个像素约 10.7 m，看起来是糊的。现在用 z13（约 15.6 m 精度）生成 4096 px 的图，每个像素约 5.4 m（`tools/terrain/build_detail_z13.py`）。
- **分支里的 `fwidth`**：`fwidth` / `dFdx` 只能在所有像素都会执行的代码里算，放进 `if` 会得到未定义的结果（比如冰晶闪光的抗锯齿）。
